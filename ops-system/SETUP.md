# Запуск системы — пошагово

Инструкция рассчитана на человека без опыта разработки. Всё делается
с телефона или планшета, кроме одного шага, где удобнее компьютер.

Время: **около часа**, из них половина — ожидание.

---

## Шаг 0. Что должно быть под рукой

| Что | Где взять |
|---|---|
| Телеграм | уже есть |
| Аккаунт Google с правом создавать таблицы | уже есть |
| Аккаунт Railway | railway.com, вход через GitHub |
| Доступ к репозиторию с кодом | уже есть |

---

## Шаг 1. Создать бота

**Это отдельный бот. Не тот, в котором личные дела.**

1. Открыть в телеграме [@BotFather](https://t.me/BotFather).
2. Отправить `/newbot`.
3. Ввести имя, которое увидит персонал — например `Ромашка Операции`.
4. Ввести логин, обязательно заканчивается на `bot` — например `romashka_ops_bot`.
5. BotFather пришлёт **токен** вида `8123456789:AAH...`.

**Токен никому не пересылать.** Кто знает токен — управляет ботом.

Сразу же, не выходя из BotFather:

6. `/setdescription` → выбрать бота → написать: `Чек-листы смены. Открытие, закрытие, замеры, фото.`
7. `/setcommands` → выбрать бота → отправить строку:
   ```
   чеклист - Заполнить чек-лист смены
   ```

---

## Шаг 2. Создать таблицу для данных

1. Открыть [sheets.new](https://sheets.new) — создастся пустая таблица.
2. Назвать её, например: `ОПЕРАЦИОННЫЕ ДАННЫЕ`.
3. Нажать **Настройки доступа** и добавить редактором:
   ```
   romashka-bot@romashka-drive.iam.gserviceaccount.com
   ```
4. Скопировать **id таблицы** из адресной строки — это кусок между `/d/` и `/edit`:
   ```
   docs.google.com/spreadsheets/d/ВОТ_ЭТОТ_КУСОК/edit
   ```

Листы и шапки создавать не надо — система сделает их сама при первом запуске.

---

## Шаг 3. Папка для фото

1. На Google Диске создать папку, например `Фото чек-листов`.
2. Дать тому же сервисному аккаунту право редактора.
3. Скопировать **id папки** из адреса — кусок после `/folders/`.

Шаг можно пропустить: без папки фото просто не сохранятся, всё остальное работает.

---

## Шаг 4. Узнать свой chat_id

1. Написать боту [@userinfobot](https://t.me/userinfobot) что угодно.
2. Он ответит числом — это `chat_id`. Записать.

То же самое делает каждый, кто будет заполнять чек-листы: управляющие,
старшие смен на кухне, повара. Их числа понадобятся на шаге 7.

---

## Шаг 5. Поднять сервис на Railway

Этот шаг удобнее с компьютера, но можно и с планшета.

1. Зайти на railway.com, войти через GitHub.
2. **New Project** → **Deploy from GitHub repo** → выбрать репозиторий.
3. Открыть созданный сервис → **Settings**:
   - **Root Directory** → написать `ops-system`
   - **Start Command** оставить пустым (возьмётся из `railway.json`)
4. Перейти в **Variables** и добавить переменные:

| Имя | Значение |
|---|---|
| `BOT_TOKEN` | токен из шага 1 |
| `DATA_SHEET` | id таблицы из шага 2 |
| `GOOGLE_SA_JSON` | содержимое файла сервисного аккаунта, целиком одной строкой |
| `ADMIN_CHAT` | твой chat_id из шага 4 |
| `PHOTO_FOLDER` | id папки из шага 3 |
| `COMPANY` | название компании |

5. Нажать **Deploy** и дождаться зелёного статуса.
6. Открыть **Deploy Logs**. Должно быть примерно так:

```
Ромашка Стрит Фуд: готовлю таблицу…
листы: Невыполнено, Идеи и задачи, Пункты, Команда, Открытие смены, Закрытие смены
Mini App на порту 8080
бот запущен
```

Если вместо этого написано `Не заданы обязательные переменные` — вернуться
к пункту 4 и дозаполнить.

---

## Шаг 6. Включить приложение

1. В том же сервисе: **Settings → Networking → Generate Domain**.
2. Получится адрес вида `ops-production-xxxx.up.railway.app`.
3. Добавить переменную `WEBAPP_URL` со значением `https://` + этот адрес.
4. Дождаться перезапуска.
5. Проверить: открыть в браузере `https://адрес/health` — должно ответить
   `{"ok": true, "company": "..."}`.

Затем в BotFather:

6. `/mybots` → выбрать бота → **Bot Settings** → **Menu Button** → **Edit menu button URL**
7. Вставить тот же адрес. Кнопка появится в самом боте слева от поля ввода.

## Шаг 7. Внести команду

Открыть таблицу из шага 2, вкладка **Команда**. Заполнить строки:

| chat_id | Имя | Точка | Роль | Активен |
|---|---|---|---|---|
| 854893099 | Азиз | ЗБ | COO | да |
| … | Владимир | ЗБ | Управляющий точки | да |
| … | Дилчу | ОВИР | Управляющий точки | да |
| … | Семён | ЗБ | Старший повар | да |

Правила:

- **Точка** определяет, за какую точку человек заполняет и что видит в истории.
- **Роль** решает, что доступно:
  - содержит «управляющ» → видит историю точки и подтверждает заполнения;
  - содержит «COO» или «директор» → видит все точки и список идей;
  - всё остальное → заполняет и видит только свои заполнения.
- **Активен** = `нет` — человек больше не может заполнять, но история остаётся.

Изменения подхватываются в течение 10 минут, перезапуск не нужен.

## Шаг 8. Проверить на себе

1. Написать боту `чеклист`.
2. Должно прийти меню с твоим именем и точкой.
3. Пройти чек-лист до конца: отметить пункты, ввести замеры, снять два фото,
   указать время.
4. Проверить в таблице: на листе «Открытие смены» появилась строка со всеми
   данными; если были невыполненные — на листе «Невыполнено» появились строки.
5. Проверить, что пришло уведомление на второй контур с кнопками
   «Проверил» и «Расхождение».

Если всё сошлось — **система работает**. Тестовую строку можно удалить.

---

## Шаг 9. Запустить людей

1. Дать каждому ссылку на бота и попросить нажать «Начать».
2. Собрать их chat_id, внести в лист «Команда».
3. На планёрке показать один проход целиком с экрана — объяснять словами
   бесполезно, показать быстрее.
4. Сказать прямо: **бумажные чек-листы отменяются с такого-то числа**.
   Пока живут оба варианта, заполнять не будут ни один.

---

## Шаг 10. Первая неделя

Каждый день смотреть, кто заполнил, а кто нет, и спрашивать про это.
Не про качество — про факт заполнения.

Это единственный шаг, который нельзя автоматизировать. Если первую неделю
не спрашивать, к третьему дню заполнять перестанут — это происходит всегда
и не зависит от того, насколько удобна система.

Через неделю придёт первый отчёт с выводами, и дальше разговор пойдёт
уже по цифрам.

---

## Что делать, если не работает

| Симптом | Причина | Что сделать |
|---|---|---|
| Бот молчит | сервис не запустился | Railway → Deploy Logs, читать последние строки |
| «Тебя нет в списке заполняющих» | chat_id не внесён или опечатка | проверить лист «Команда», число без пробелов |
| Кнопка приложения не появилась | не задан `WEBAPP_URL` | шаг 6 |
| Приложение открылось, но пишет «нет доступа» | адрес в BotFather не совпадает с `WEBAPP_URL` | сверить, должны совпадать до символа |
| Фото не сохраняются | нет `PHOTO_FOLDER` или нет доступа | шаг 3 |
| Данные не пишутся | сервисному аккаунту не дали редактора | шаг 2, пункт 3 |

## Для следующего клиента

Шаги те же, меняются три вещи:

1. Свой файл чек-листов — скопировать `checklists.romashka.json`, переписать
   под процессы клиента, путь указать в переменной `CHECKLISTS_FILE`.
2. Свой сервисный аккаунт Google и своя таблица.
3. Свой бот.

Код не меняется. Это и есть смысл разделения: система ставится новой компании
за час, без единой правки в программе.
