# Операционная система точек

Чек-листы смены, контроль в два круга и отчётность для сети общепита.
Работает в телеграме — приложением и в чате. Данные ложатся в Google Sheets.

Собрано на «Ромашка Стрит Фуд», но к ней не привязано: всё, что отличает
одну компанию от другой, лежит в конфиге.

---

## Что решает

Чек-листы на бумаге не дают отчётности: лист лежит на точке, руководитель его
не видит, а через месяц по нему ничего не восстановить. Электронные чек-листы
дают другую проблему — их отмечают не глядя, потому что «поставить галочки»
быстрее, чем сходить и проверить.

Система бьёт по второй проблеме четырьмя механизмами:

1. **Ничего не отмечено заранее.** Каждый пункт надо нажать: выполнено или нет.
   Проскочить одной кнопкой нельзя.
2. **Где нужен замер — спрашивается число,** а не галочка: температуры камер,
   наличные в кассе. Соврать можно, но это уже осознанное действие.
3. **Фото случайных пунктов.** Каждый раз система просит снимки двух пунктов
   наугад из тех, где снимок обязателен. Заранее не подготовишь.
4. **Время засекается.** Быстрее норматива точку физически не обойти — такие
   заполнения помечаются и уходят руководителю.

И два круга контроля: заполняет смена, подтверждает управляющий, выборочно
проверяет операционный директор. Кто не подтвердил — видно в отчёте.

## Что внутри

| Модуль | За что отвечает |
|---|---|
| `app/config.py` | конфигурация: секреты из окружения, чек-листы из JSON |
| `app/storage.py` | Google Sheets и Drive: структура таблицы создаётся сама |
| `app/bot.py` | телеграм-бот: меню по ролям, чек-лист в чате, история, проверка |
| `app/webapp.py` | Mini App: та же работа страницей внутри телеграма |
| `app/reports.py` | дневной блок и недельная сводка с выводами |
| `app/main.py` | точка входа: поднимает бота и Mini App |
| `web/index.html` | страница Mini App |
| `checklists.*.json` | сами чек-листы — данные, не код |

## Установка

Пошагово, для человека без опыта разработки — **[SETUP.md](SETUP.md)**.
Коротко:

1. **Бот.** Создать у [@BotFather](https://t.me/BotFather), забрать токен.
2. **Таблица.** Создать пустую Google-таблицу, дать сервисному аккаунту право
   редактора. Листы и шапки система создаст сама при первом запуске.
3. **Переменные.** Скопировать `.env.example`, заполнить.
4. **Запуск:** `python -m app.main`

Проверить отчёт, ничего не отправляя:

```bash
python -m app.main --week      # недельная сводка в консоль
python -m app.main --day       # что было вчера
python -m app.main --week --send   # отправить руководителю
```

## Кто может заполнять

Лист **«Команда»** в таблице: `chat_id · Имя · Точка · Роль · Активен`.
Роль определяет, что человек видит:

| Роль | Что доступно |
|---|---|
| любая другая | заполнить чек-лист, свои последние заполнения |
| Управляющий | плюс история своей точки и подтверждение заполнений |
| COO / директор | плюс все точки и список идей с точек |

Правится в таблице, код трогать не надо.

## Свои чек-листы

`checklists.romashka.json` — пример. Формат:

```json
{
  "open": {
    "title": "Открытие смены",
    "code": "03-CL-01",
    "ask_time": "Во сколько открылись?",
    "measures": { "14": {"q": "Температура холодильников",
                         "norm": "+2…+6", "unit": "°C"} },
    "blocks": [
      { "name": "1. Персонал",
        "items": [ {"text": "Смена вышла в полном составе",
                    "norm": "за 60 мин до открытия", "photo": false} ] }
    ]
  }
}
```

Нумерация пунктов сквозная и проставляется сама. Ключи в `measures` — номера
пунктов, к которым привязан замер. `photo: true` — пункт попадает в список тех,
из которых система выбирает случайные снимки.

Путь к своему файлу — переменная `CHECKLISTS_FILE`.

## Пороги и расписание

Меняются переменными окружения, не кодом:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `TZ_OFFSET` | 5 | часовой пояс точки относительно UTC |
| `PHOTOS_PER_RUN` | 2 | сколько случайных фото просить за раз |
| `MIN_SECONDS` | 180 | быстрее — считаем заполнение формальным |
| `REPEAT_FAIL` | 3 | столько провалов пункта за неделю = сломан процесс |
| `CHECK_GAP` | 0.7 | ниже доли подтверждений — второй контур не работает |
| `DAILY_AT` | 21:30 | во сколько уходит итог дня |
| `WEEKLY_AT` | 09:30 | во сколько в понедельник уходит сводка недели |

Дедлайны чек-листов лежат в самом файле чек-листов — `deadline` и
`remind_before` (за сколько минут напомнить).

## Три круга контроля

| Круг | Кто | Что получает |
|---|---|---|
| 1 | смена | напоминание за 45 мин до дедлайна, потом сам чек-лист |
| 2 | управляющий точки | полный список — что сделано и что нет — с кнопкой подтверждения |
| 3 | операционный директор | итог после подтверждения, просрочки, замеры вне нормы |

Итог дня и сводка недели приходят и управляющему (по его точке),
и директору (по всем).

## Проверка фото моделью зрения

Необязательный слой. Без ключа выключен и ни на что не влияет.

Модель получает **эталонный снимок** и **текст пункта** и отвечает, выполнено
ли требование. Это не попиксельное сравнение: свет, ракурс и время суток
каждый раз разные, и сравнение картинок дало бы мусор.

| Переменная | Смысл |
|---|---|
| `GEMINI_API_KEY` | ключ Google AI Studio; пусто — проверка выключена |
| `GEMINI_MODEL` | по умолчанию `gemini-2.5-flash` |

Эталоны задаются в листе **«Пункты»**, колонка **«Эталонное фото»** — ссылка
на снимок в Drive. Нет эталона — модель судит по одному тексту пункта.

Вердикт пишется в колонку **«Фото — проверка ИИ»**. Если модель нашла
расхождение, управляющему уходит сообщение с прямой оговоркой: это мнение
модели, а не факт нарушения.

Промпт намеренно осторожный: при любом сомнении модель обязана ответить
«похоже на правду». Ложное обвинение дороже пропущенного нарушения.

## Чего пока нет

- месяц, квартал, год — только день и неделя;
- веб-дашборд — отчёты приходят в телеграм;
- несколько компаний в одной установке — одна установка на компанию.
